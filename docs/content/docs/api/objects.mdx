## Object shapes

### object

<DecoderSig
  name="object"
  params="{ field1: Decoder<A>, field2: Decoder<B>, ... }"
  type="{ field1: A, field2: B, ... }"
  source="objects.ts#L168-L178"
  multiline
/>

Accepts objects with fields matching the given decoders. Extra fields that exist on the
input object are ignored and will not be returned.

<DecoderPlayground
  decoder="object({ x: number, y: number })"
  examples={['{ x: 1, y: 2 }', '{ x: 1, y: 2, z: 3 }', '{ x: 1 }']}
/>

Read more here about [the differences between](#whats-the-difference) `object`, `exact`,
and `inexact`.

### inexact

<DecoderSig
  name="inexact"
  params="{ field1: Decoder<A>, field2: Decoder<B>, ... }"
  type="{ field1: A, field2: B, ... }"
  source="objects.ts#L217-L267"
  multiline
/>

A "loose object" decoder. Like [`object()`][], but will pass through any extra fields on
the input object unvalidated that will thus be of `unknown` type statically.

The one exception is a `__proto__` key, which cannot be passed through safely. See
[Unsafe keys](#unsafe-keys).

<DecoderPlayground
  decoder="inexact({ x: number, y: number })"
  examples={['{ x: 1, y: 2 }', '{ x: 1, y: 2, z: 3 }', '{ x: 1 }']}
/>

Read more here about [the differences between](#whats-the-difference) `object`, `exact`,
and `inexact`.

### What's the difference?

The three decoders in the "object" family are very similar and differ only in how they
treat extra properties on input values.

<DecoderPlayground
  globals={{
    fields: '{ x: number, y: number }',
  }}
  preface={`
    const fields = {
      x: number,
      y: number,
    };
  `}
  decoder={[
    ['object', 'object(fields)'],
    ['exact', 'exact(fields)'],
    ['inexact', 'inexact(fields)'],
  ]}
  examples={['{ x: 1, y: 2, z: 3 }', '{ x: 1, y: 2 }']}
/>

---

### Unsafe keys

`__proto__` is the only key that cannot be written to a plain object without reassigning
its prototype instead of adding a field. Decoded results therefore never contain one:

| decoder     | input containing a `__proto__` key   |
| ----------- | ------------------------------------ |
| `object()`  | ignored, like any other unknown key  |
| `exact()`   | rejected                             |
| `inexact()` | rejected, rather than passed through |
| `record()`  | rejected                             |

Where a decoder rejects, the error is reported on the `__proto__` field itself, so it
reads like any other field error:

```text
{
  "theme": "dark",
  "__proto__": {
    "isAdmin": true,
  },
               ^ Unsafe key
}
```

Declaring a `__proto__` key in a decoder definition throws. If you genuinely need to read
a field named `__proto__`, write a custom decoder with [`define()`][].

## Dictionary shapes

### record

<DecoderSig
  name="record"
  params="values: Decoder<V>"
  type="Record<string, V>"
  source="collections.ts#L8-L68"
/>

<DecoderSig
  name="record"
  params="keys: Decoder<K>, values: Decoder<V>"
  type="Record<K, V>"
/>

Accepts objects where all values match the given decoder, and returns the result as a
`Record<string, V>`.

This is useful to validate inputs like `{ [key: string]: V }`.

Inputs containing a `__proto__` key are rejected. See [Unsafe keys](#unsafe-keys).

#### Decoding values only

The default call takes a single argument and will validate all _values_. For example, to
validate that all values in the object are numbers:

<DecoderPlayground
  decoder="record(number)"
  examples={['{ red: 1, blue: 2, green: 3 }', "{ hi: 'not a number' }"]}
/>

#### Decoding keys and values

If you also want to validate that keys are of a specific form, use the two-argument form:
`record(key, value)`. Note that the given key decoder must return strings.

For example, to enforce that all keys are emails:

<DecoderPlayground
  decoder="record(email, number)"
  examples={["{ 'me@nvie.com': 1 }", "{ 'no-email': 1 }"]}
/>
